# Development Task Planner

Простое консольное приложение для ведения проектов и задач разработки. В ПР3 проект из ПР2 переведён со словарей на объектную модель.

## Возможности

- создание и просмотр проектов;
- создание задач с приоритетом и дедлайном;
- поиск, фильтрация и сортировка задач;
- назначение исполнителя с проверкой роли;
- изменение прогресса и автоматический статус;
- просмотр ближайших дедлайнов и статистики;
- загрузка и сохранение данных в JSON.

## Объектная модель

### `Project`

Хранит идентификатор, название и описание проекта. Методы `from_data()` и `to_dict()` преобразуют данные при загрузке и сохранении, а `__str__()` формирует строку для интерфейса.

### `User`

Хранит имя и роль исполнителя. Статический метод `is_valid_role()` разрешает роли `developer`, `tester` и `teamlead`.

### `Task`

Хранит задачу и ссылку на объект `Project`. Исполнитель хранится как объект `User`. Методы `assign()`, `update_progress()` и `urgency()` изменяют и анализируют состояние задачи. Свойство `status` возвращает статус по прогрессу.

Связи объектов:

```text
Task -> Project
Task -> User (если исполнитель назначен)
```

## Структура

```text
development-task-planner/
├── main.py              # меню приложения
├── models/              # классы предметной области
│   ├── __init__.py      # общий импорт классов
│   ├── project.py       # класс Project
│   ├── user.py          # класс User
│   └── task.py          # класс Task
├── projects.py          # операции с коллекцией проектов
├── tasks.py             # операции с коллекцией задач
├── storage.py           # преобразование объектов и JSON
├── utils.py             # безопасный ввод и разбор дат
├── data/
│   ├── projects.json
│   └── tasks.json
├── tests/               # тесты pytest
├── output/pdf/          # отчёты по практическим работам
├── requirements.txt
└── setup.cfg
```

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

## Проверка

```bash
python -m pytest -q
flake8 .
```

Тесты проверяют создание объектов, методы классов, связи `Task` с `Project` и `User`, работу функций над коллекциями, сохранение в JSON и восстановление объектов.

## Хранение данных

Формат JSON сохранён совместимым с ПР2. При загрузке словари преобразуются в объекты. При сохранении методы `to_dict()` возвращают обычные структуры данных. Для связи задачи с проектом в JSON хранится `project_id`.
